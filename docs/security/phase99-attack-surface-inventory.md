# Phase 99 — Attack Surface Inventory

This document is the narrative companion to the machine-readable inventory at
`docs/security/phase99-route-security-inventory.json`, generated by
`scripts/security/phase99/route-inventory.mjs` and kept from drifting by
`node scripts/security/phase99/generate-inventory.mjs --check`. Where the JSON
is authoritative and exhaustive, this document explains *why* the surface is
shaped the way it is and walks the trust boundaries an external reviewer will
actually be crossing.

## Classification model

Every exported HTTP handler under `src/app/api/**/route.ts` is classified
fail-closed: a handler is only ever `PUBLIC_READ`, `PUBLIC_WRITE`, `WEBHOOK`
or `INTERNAL_HEALTH` because it is named on an explicit, justified allowlist
(`scripts/security/phase99/public-surface.mjs`); otherwise it must prove
authorization evidence in its own source (`AUTHENTICATED_USER`,
`TENANT_MEMBER`, `PLATFORM_ADMIN`) or it is `UNKNOWN`, and `UNKNOWN` fails
readiness. There is no "probably fine" bucket. At the time of writing the
inventory holds 355 route files and 497 handlers:

| Classification | Handlers |
|---|---:|
| `PUBLIC_READ` | 36 |
| `PUBLIC_WRITE` | 13 |
| `AUTHENTICATED_USER` | 210 |
| `TENANT_MEMBER` | 119 |
| `PLATFORM_ADMIN` | 115 |
| `WEBHOOK` | 2 |
| `INTERNAL_HEALTH` | 2 |
| `UNKNOWN` | 0 |

Three entries on the public-surface allowlist were found, during the Phase 99
review, to be wrong rather than intentional — a course-detail endpoint, a
quiz-detail endpoint and a job-detail endpoint that returned unpublished or
cross-tenant records — and were fixed rather than declared public (findings
`P99-INT-004`, `P99-INT-005`, `P99-INT-006` in
`docs/security/phase99-findings.json`). Every remaining allowlist entry
carries a written justification naming what the handler actually returns.

## Unauthenticated write surfaces

All 13 `PUBLIC_WRITE` handlers, with the control each one carries. "Rate
limit" names the bucket in `src/lib/auth/rate-limiter.ts`; "bounded body" and
"media-type check" refer to `readBoundedTextBody` / `readBoundedJson` and
`isJsonContentType` in `src/lib/security/request-guards.ts`.

1. **`POST /api/copilot/demo`** — anonymous product demo. Rate limited
   (`copilot-demo-post`, 12/min per client IP), bounded body, media-type
   checked. Runs a deterministic in-process pipeline with no Prisma,
   provider or model call.
2. **`POST /api/industrial-brain/analyze`** — anonymous deterministic fault
   analysis. Rate limited (`industrial-brain-analyze`, 12/min), bounded
   body, media-type checked (added by `P99-INT-012`). The analyzer reaches
   no database, provider or model and echoes only the caller's own input.
3. **`POST /api/compliance/cookie-consent`** — pre-authentication consent
   collection. Rate limited (`cookie-consent`, 30/min). Keyed on an opaque,
   server-minted `hermes_consent_id` cookie; the authentication session
   cookie is never read or written by this route, and a client-supplied
   session identifier is ignored outright (`P99-INT-001`, `P99-INT-002`).
4. **`POST /api/auth/register`** — public self-registration is disabled: the
   handler returns `403` with no logic behind it and reads no body.
5. **`POST /api/auth/access-request`** — access request for a closed
   platform. Rate limited (`access-request`, 5/hour) and honeypot-guarded;
   writes a sales-lead record only and never creates a user or grants access.
6. **`POST /api/auth/accept-invite`** — invitation redemption. Rate limited
   (`accept-invite`, 10/hour per client IP). The single-use hashed
   invitation token is the credential; the granted role comes from the
   invitation record, never from the request.
7. **`POST /api/auth/forgot-password`** — password-reset initiation. Rate
   limited (`forgot-password`, 3/hour). The response is identical whether or
   not the supplied address exists, so it does not enumerate accounts.
8. **`POST /api/auth/reset-password`** — password-reset completion. Rate
   limited (`reset-password`, 5/hour). The single-use reset token is the
   credential.
9. **`POST /api/auth/verify-email`** — email verification. Rate limited
   (`verify-email`, 10/hour). The single-use verification token is the
   credential.
10. **`POST /api/candidate/register`** — candidate self-registration for the
    public careers portal. Rate limited (`candidate-register`, 5/hour),
    media-type checked, body-bounded; creates only a candidate-scoped
    identity.
11. **`POST /api/careers/apply`** — public job application. Rate limited
    (`careers-apply`, 5/hour), media-type checked, body-bounded; the
    organization is taken from the job record, never from the request.
12. **`POST /api/vendors/apply`** — public vendor onboarding request. Rate
    limited (`vendor-apply`, 5/hour, added by `P99-INT-009`), media-type
    checked, body-bounded, and no longer reads or stores the authentication
    cookie. Creates a pending request that an administrator must approve.
13. **`POST /api/sales/leads`** — public contact form. Honeypot-guarded and
    rate limited on `resolveClientIp` (`X-Real-IP` only, fixed by
    `P99-INT-008` after the limiter was found keying on the client-controlled
    `X-Forwarded-For` header); writes a sales-lead record only.

Every one of these routes creates or updates a database row (or, for the two
demo/analysis routes, does neither) but none of them authenticates a caller
or returns another party's data — the control that matters for each is
"can this be used to flood the table or exhaust a resource," which is why
rate limiting and body bounding are the two controls checked mechanically by
the `API_SECURITY` group of `npm run eval:phase99:readiness`.

## Trust boundaries

**Browser → nginx.** TLS terminates at nginx. Client-supplied
`X-Forwarded-For` is appended to, not trusted, by the proxy; `X-Real-IP` is
overwritten by nginx to the actual peer address (`proxy_set_header
X-Real-IP $remote_addr`) and is the only header the application trusts for
rate-limit keying (`resolveClientIp` in
`src/lib/security/request-guards.ts`). Cookies set by the application are
`httpOnly`, `Secure` in production, and `SameSite=Lax` (session) or
`SameSite=Strict` (access/refresh tokens), so the CSRF contract is
SameSite-primary: a cross-site request simply does not carry them.

**nginx → app.** The Next.js application container is reached only through
the reverse proxy on the internal Docker network; it does not publish a host
port of its own in the production Compose configuration. Security response
headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`) are
set in `next.config.ts`, and a nonce-based Content-Security-Policy is set in
`src/middleware.ts` per request.

**App → PostgreSQL / Redis.** Both data services run on the internal Docker
network with no published host ports. All application queries go through
Prisma; the seven raw-SQL sites in the codebase are literals,
parameter-bound templates, or constant identifiers — see
`phase99-test-matrix.md#sql-injection`. Redis backs the rate limiter and
session/consent state, with an in-process fallback that is fail-safe (tighter
under degradation), never fail-open.

**App → outbound providers.** No API route lets a request decide an outbound
destination (`SSRF_USER_CONTROLLED_SINKS=0`, proven by
`userControlledSinkScan` in `scripts/security/phase99/static-invariants.mjs`).
Outbound sinks are module-level constants, environment-configured (Stripe,
the alert webhook, IndexNow submission), or same-origin relative paths used
by browser-side OT wrappers. Four sinks whose destination is a helper
parameter rather than resolvable at the call site are reviewed individually
in `SSRF_SINK_ALLOWLIST` in the same module, each with a written
justification.

**OT gateway → app.** Industrial edge gateways authenticate to a dedicated
ingestion surface using an HMAC-signed envelope rather than a session cookie;
the tenant is read from the gateway's own record, never accepted from the
envelope. Ingestion is rate limited in two stages — a tight pre-authentication
bucket keyed by client IP that applies before any database lookup or HMAC
work, and a per-gateway post-authentication bucket so one noisy device cannot
consume another gateway's budget behind the same network address. No live OT
equipment is reachable from, or a target of, anything in this repository or
this review package — see `phase99-external-review-scope.md` and
`phase99-rules-of-engagement.md`.
