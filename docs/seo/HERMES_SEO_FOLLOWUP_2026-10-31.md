## 2. Live robots.txt has two sources of truth ✅ (LIVE, owner/Cloudflare action)

Observed 2026-10-31 (summarised fetch; re-verify raw):

- The served `/robots.txt` contains a `# BEGIN Cloudflare Managed content` … `# END Cloudflare Managed Content`
  block **prepended** to the file generated by `src/app/robots.ts`. The 2026-10-15 baseline recorded 22 UA
  groups and no Cloudflare block, so this appeared after that date.
- The Cloudflare block adds `Content-Signal: search=yes,ai-train=no,use=reference` under `User-agent: *` and
  `Disallow: /` groups for ~32 agents, including `GPTBot`, `ClaudeBot`, `Google-Extended`,
  `Applebot-Extended`, `CCBot`, plus two search engines (`Baiduspider`, `PetalBot`).
- The app's own policy (Phase 62 owner decision, `trainingTier(...)` in `src/app/robots.ts`) deliberately
  grants those training agents `/library/`, `/services/`, `/academy/`. The two blocks now contradict each other;
  RFC 9309 merges same-agent groups, so the effective result depends on rule length and differs per crawler.
- The file is ~2,700 lines; the `Sitemap:` line emitted by the app sits at the very end.

**Action (owner):** Cloudflare dashboard → the zone → Security / Bots → "Manage your robots.txt" (label may
differ) → **off**, so the app-generated file is the only source. If the owner instead wants
`ai-train=no` site-wide, change `trainingTier` in `src/app/robots.ts` to match and keep Cloudflare off —
one source either way. Then: `curl -s https://hermesnovin.com/robots.txt | grep -c "Cloudflare Managed"` → `0`,
and the `Sitemap:` line is present.
